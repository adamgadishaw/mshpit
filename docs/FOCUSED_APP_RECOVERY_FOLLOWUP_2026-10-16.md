## Reproduced defects and corrections

| Trigger and previous behavior | Correction and evidence |
| --- | --- |
| A successful `/api/me` reply omits `user`, contains an empty body, or supplies a false, zero or empty-string user. The client treats it as an authoritative guest verdict, clears the confirmed session and stops recovery. Malformed object or boolean IDs can also become replacement identities. | Only explicit `user: null` confirms guest. An account requires a non-array object with a nonempty string ID; malformed replies use the existing recovery path. Ordinary checks preserve the confirmed UI, while cold starts and strict cross-tab validation remain locked. Seventeen actual-source tests execute the complete Store identity effect, API parser, coordinator and auth transitions with synthetic transport. Before: 10 failures; after: all pass. Valid guest, HTTP 401 expiry and explicit logout still retire the account. |
| Discover accepts retained dates such as `2026 · 10 · 05` through its server projection, API parser and range filter, but its weekly List accepts only strict ISO dates. Those accepted shows disappear from the default native List. The old list parser also permits impossible ISO calendar days to roll into another date. | Weekly grouping uses the existing shared calendar validator and constructs canonical day keys without modifying event data. The regression traverses the actual server date canonicalizer, API parser, Store sanitizer, range filter and week grouper. Retained dates appear in the correct weeks; impossible dates are excluded. |
| Discover's later-page request fails after earlier shows have loaded. The retained cursor makes the List keep announcing `Adding later dates...` indefinitely alongside the retry action. | The later-page indicator requires an active loading state. The actual screen request, Store loader, API adapter and evaluated List JSX verify pending, rejected and recovered page transitions while retaining existing shows. |
| Clips retries a failed native player, or leaves and reactivates a failed clip. Expo's `useEvent` retains the previous emitter's last error across player replacement, so the fresh player inherits an error before it has failed. A rejected playback start can likewise leak its failure into the next activation. | Native player status and start rejection are scoped to the player instance. Retired events cannot replace the new player's status, and a new player begins with its own current status. Actual React reconciliation with the installed Expo event hook reproduces four baseline status failures across Android/iOS retry and reactivation paths; a separate rejected-start regression covers the corresponding playback-control failure. |
| Clips' retry panel spreads `StyleSheet.absoluteFillObject`, which is absent from the installed React Native 0.86 API. The panel loses its absolute bounds and becomes a normal layout sibling after the full-height video. | The panel uses the supported absolute-fill style so the failure and retry controls cover the video stage. |
| The disposable mobile backend preload hardcodes the original checkout path, so `npm run mobile:backend` fails before startup from a new worktree. | The preload derives its own repository root from its module URL and still rejects invocation from another directory. Its regressions verify disposable database placement, removal of inherited secrets, blocked outbound transports and loopback-only listening. Before: one failure of two tests; after: two pass. |
| A decoded frame arrives while native play or pause is still queued. Clips infers pause intent from the temporary `playing` value, cancelling autoplay on entry, retry or foreground return, or reversing an explicit pause. On web, the same update can cancel the pending autoplay rejection handler. | First-frame readiness no longer overwrites play/pause intent. Five added actual-React regressions exercise deferred native commands and a decoded frame preceding web autoplay rejection. Before the intent correction: 7 of 12 lifecycle tests pass; after: 12 of 12. Normal coordinate touch on the isolated Android fixture also reproduced the autoplay cancellation before this correction. |
