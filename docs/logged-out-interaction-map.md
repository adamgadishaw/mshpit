# Logged-out interaction map

Audit snapshot: 2026-09-09, working changes based on `455488a`. This is an implementation checklist, not a claim that every authentication or concurrency path is defect-free. No actual backend crash was reproduced. Confirmed failures were guest controls that did nothing, navigated to the wrong place, or allowed guest-only optimistic state changes.

## Shared boundary

- [App.js](../App.js), `openSignIn` (line 578), pushes a separate auth frame above the current public screen and suppresses duplicate top-level auth frames. Closing sign-in returns to that screen. No attempted Like, reply, rating, attendance, join, or publish action is queued for replay after login.
- `requireAuth` gates private navigation; `requireVerifiedMutation` additionally uses [emailVerificationUx.mjs](../src/domain/emailVerificationUx.mjs): guests open sign-in, unverified members see the existing verification prompt. These are usability guards, not server authorization.
- App's `confirmedNavigationAccountRef` layout effect clears account-specific navigation/composer/viewer state after an authoritative account change. Ordinary same-account revalidation preserves the workspace. Entry-point guards do **not** constitute a universal validator for every fabricated or restored navigation frame.
- [server/requestAuthorization.js](../server/requestAuthorization.js), `readAuthorizedRequest`, resolves identity after reading the body and checks expected-account binding. [server/api.js](../server/api.js), `requireSessionUser` / `requireUser` (lines 356/364), rejects absent sessions with `401 AUTH_REQUIRED` and enforces applicable account restrictions. [accountMutationAccess.js](../server/accountMutationAccess.js) separately enforces verification/dormancy, with explicit recovery/privacy/safety exceptions; individual routes retain ownership, visibility, membership, payload and rate checks.

## Public POST exceptions and analytics policy

- `POST /api/media/reactions` ([api.js](../server/api.js), 4462) reads aggregate reactions for permitted media; it is distinct from the protected singular `/api/media/react` mutation.
- `POST /api/feed/revalidate` (5941) reads visibility/invalidation status for supplied post IDs. Do not classify it as a guest write merely because its method is POST.
- [SuggestionBoxScreen.jsx](../src/screens/SuggestionBoxScreen.jsx) is reachable from landing/menu without login. [suggestionRoutes.js](../server/features/suggestions/suggestionRoutes.js), `POST /api/suggestions`, intentionally accepts anonymous product feedback, validates text/idempotency, and limits submissions to 5/hour and 12/day. Signed-in callers retain account safety restrictions. The suggestion service does not automatically attach account/contact/IP/search text/page URL; this is unrelated to personalized people suggestions.
- `POST /api/analytics/guest-search` intentionally stores only daily counts by search kind, result bucket and success/failure. [guestSearchAnalyticsRoutes.js](../server/features/guestSearchAnalytics/guestSearchAnalyticsRoutes.js) rate-limits it; [guestSearchAnalytics.js](../server/guestSearchAnalytics.js) ignores signed-in callers and retains a bounded 90-day window. Search text, account/device IDs, URLs, IPs and exact timestamps are not stored in these aggregate rows; request address is used by the expiring in-memory rate limiter.
- Account-linked `/api/events` and `/api/events/batch` are different: [analyticsService.js](../server/analyticsService.js), `ingestAnalyticsBatch`, records nothing for guests and requires the member's analytics-consent policy. Guest no-op acceptance is not permission to create account events. Feed impressions/preferences remain member-bound.

## Store defense and completed evidence

The Store defense is implemented. [store.js](../src/store.js), `currentMutationActor` (511), binds the rendered action to the current confirmed account and account epoch. `addLog` (3425), `deleteOwnPost` (4400), `toggleLike` (4454), and `toggleMediaReaction` (2005) reject guest, unready, switched, logged-out, or stale-render actions before state/cache/network writes. Requests bind `expectedAccountId`; late success/failure cannot publish or roll back into a different account epoch. Same-account profile refreshes remain valid. Existing guards remain on comments, attendance, reviews, follow, DMs, ratings and club membership; this audit did not rewrite every mutation facade.
