## Intended correction

- Add request-local, strictly categorical resolver diagnostics and bounded
  process-local aggregate measurements. Distinguish saved source, both provider
  outcomes, work origin, elapsed timings and cache-write outcome. Keep raw
  lookup text, identities, query strings, IPs, user agents, credentials and
  request/response bodies out of new diagnostic fields. Diagnostic failures
  must not change the resolver's result or failure.
- Make the alert scheduler wake once at the next permitted send time when an
  eligible pending alert was deferred by cooldown. Preserve eligibility,
  cooldown policy, frozen batches, provider idempotency and acknowledged counts.
  Do not add automatic retries after failed sends or automatic startup mail.

The existing MusicBrainz six-second and Deezer 1.5-second work deadlines,
hedging, rate limits, matching, cancellation, caches and manual user recovery
are unchanged. No new public error code, provider, dependency, schema or
configuration is required.

### Measurement boundaries

The existing staff health projection exposes fixed counters in 60 one-minute
process-local buckets. `storedMatches / completed` measures successful saved
matches among resolver handler completions, including validation and rate-limit
failures in the denominator. It does not count all HTTP arrivals or people;
hidden identities do not enter the numerator. The optional Referer is reduced
immediately to a fixed same-origin page category. It is client-controlled and
cannot identify a visitor, bot or reliable traffic source.

Provider elapsed time measures the subscribed operation, including shared work,
memoization and queue time. `new_work` means a work object was created, not that
an HTTP request reached the provider. A cancelled loser describes this caller's
subscription; shared work may continue for another caller. Only existing error
log lines receive a bounded categorical suffix. There are no new success logs,
raw request fields, timers or persistent diagnostic records.

### Alert delivery boundaries

All existing automatic alert triggers share one scheduler. Eligible pending
alerts deferred by cooldown receive one wake-up at the next permitted time.
Successful capped batches recheck the backlog and preserve the cooldown between
batches. A failed or skipped delivery does not create a retry; a genuinely new
incident arriving during delivery retains its trigger. Manual sends, backwards
clock movement and shutdown preserve those rules. Restart adds no startup send;
the next existing trigger reads the durable successful-send cooldown.

## Remaining limits

Diagnostics cannot reconstruct pre-deployment lookup-source history or turn a
saved result into proof of external-provider health. Process-local summaries
expire and reset when the process restarts. Provider failures without a usable
saved match can still return 502. The scheduler correction addresses deferred
delivery; it does not correct a failed lookup or prove that the reported email
was delayed. A later release requires owner approval, current CI and separate
exact-commit deployment verification.
